# PWA / offline app shell

This document covers the **web PWA layer**: a service worker that precaches the
application shell so the site opens without network. It complements — and does
not replace — the local-first data layer described in `offline-sync.md`.

## What it does

- Precaches the built app shell (`index.html`, JS/CSS chunks, icons, fonts and
  the `public/locales/*.json` bundles) so the SPA boots offline.
- Serves navigations from the precached `index.html` (SPA fallback).
- Runtime-caches Google Fonts (stylesheets + webfonts) so typography survives
  offline.
- Shows a small prompt when a **new build** is deployed; the user can reload
  now or later (`registerType: "prompt"`).
- Shows a one-off toast the first time everything needed is cached and the app
  is ready to work offline.

## What it does NOT do

- It never caches API responses. The offline data story belongs to the sync
  engine (IndexedDB + outbox), not the HTTP cache.
- It never intercepts `/api/*`, `/uploads/*` or `/ws*`. Those paths are
  excluded both from runtime caching and from the SPA navigation fallback:

```ts
navigateFallbackDenylist: [/^\/api\//, /^\/uploads\//, /^\/ws(\/|$)/]
```

- It is **not** registered on native builds. Capacitor already bundles the
  assets on device; `PwaUpdater` is rendered only when
  `import.meta.env.PROD && !isNative()` (see `src/App.tsx`).

## Files

```
vite.config.ts                 VitePWA plugin, manifest and workbox options
src/pwa/PwaUpdater.tsx         SW registration + update/offline-ready toasts
src/vite-env.d.ts              `vite-plugin-pwa/react` type reference
public/icons/                  PWA icons (192, 512, maskable 512, apple 180)
public/locales/*/translation.json  `pwa.*` strings
```

`public/manifest.webmanifest` used to exist as a hand-written (and unused,
broken) file; it was removed. The manifest is now generated by the plugin from
the `manifest` option and written to `dist/manifest.webmanifest`.

## Configuration highlights (`vite.config.ts`)

- `injectRegister: false` — the plugin does **not** inject a registration
  script; registration happens from React in `PwaUpdater`, gated to web prod
  builds. This keeps native bundles clean.
- `registerType: "prompt"` — updates wait for user confirmation.
- `disable: mode === "test"` — Vitest never generates or registers the SW.
- `globPatterns` include `json` so the i18next locale files are available
  offline. `maximumFileSizeToCacheInBytes` is raised to 4 MiB (the main bundle
  is ~1.2 MiB).

## Icons

Icons live in `public/icons/` and are generated once from the source art in
`frontend/icons/` (these `.webp` files are actually PNGs):

```sh
cp icons/icon-192.webp public/icons/icon-192.png
cp icons/icon-512.webp public/icons/icon-512.png
convert icons/icon-512.webp -background '#181851' -flatten public/icons/icon-maskable-512.png
convert icons/icon-192.webp -background '#181851' -flatten -resize 180x180 public/icons/apple-touch-icon.png
```

The maskable variant flattens the rounded-square artwork onto the brand navy
(`#181851`) so Android launchers can crop it into any shape.

## Testing locally

The service worker is only generated on production builds, so use preview:

```sh
npm run build
npm run preview      # http://localhost:4173
```

- Load the site once, then in DevTools → Application → Service Workers confirm
  the SW is activated and the caches are populated.
- Enable "Offline" in DevTools (or stop the backend) and reload: the shell
  should still render.
- Deploy a new build and reload: the update toast/prompt should appear.

In `npm run dev` there is no service worker (`devOptions.enabled: false`).

## Deployment notes

- Service workers require a secure context: HTTPS, or `localhost` during
  development.
- nginx serves the SPA and proxies `/api`, `/uploads` and `/ws`. The SW is
  served from the web root (`/sw.js`, scope `/`), so `location /` must keep
  serving it as a static file (it does, via `try_files`).
- If a Content-Security-Policy is ever enforced on the SPA, keep the default
  `worker-src`/`child-src` fallback allowing `'self'` so the worker can load.
